# Adapter contract

A consumer keeps its own authoritative source, domain and rules. Register an adapter locally only when a real task benefits. Record local source/version, supported mode/class, opt-in or local mandate, sources and permitted knowledge, privacy restrictions, output destination, write authority and acceptance checks. Do not duplicate the core or treat a local copy as an independent release authority. Resolve current local sources before using a profile.

| Generic field | Adaptation | Non-transferable authority |
|---|---|---|
| Documentary debate | Lens/Table/Counterproof; public sources | Evidence and position of the real person |
| Fiction and creative writing | World/Table/Counterproof; character knowledge and canon | Author's canon, original manuscripts, voice |
| Theory and essay | Lens and counterargument grounded in sources | Authorial thesis, evidence, citations |
| Biography/archives | Reception, curatorial roles, consented Mirror when appropriate | Original memory, consent, privacy and historical text |
| Institutional deliberation | Functional chairs where local procedure permits | Quorum, vote, mandate, actual agent registry |
| Professional reception | Hypotheses and functional roles | Real decisions, credentials, employment outcomes |
| Clinical/high-risk education | Authorized generic synthetic roles only | Patient data, records, diagnosis, legal or clinical judgment |

No private profile or corpus is exported by an adapter. No default activation for every task. Version pins describe the actual retrieved release. If unavailable, use the supplied candidate only with accurate state. For an authorized write, the local source's gate and readback rule applies. Without a writeback mandate, output remains a candidate.
